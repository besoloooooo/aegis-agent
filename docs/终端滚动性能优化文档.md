# 终端滚动性能优化：视口裁剪实现

## 概述

本文档详细分析了 Hermes 和 Claude Code 的终端渲染实现，以及如何在 Aegis Agent TUI 中实现视口裁剪优化，以解决终端滚动卡顿问题。

## 1. 问题分析

### 1.1 原始性能问题

Aegis Agent 的终端界面在滚动长对话历史时出现卡顿，主要原因：

- `_formatted_output()` 方法在每次渲染时都会处理所有历史行（最多4000行）
- 即使只有约50行可见，也需要连接和渲染所有行
- 每次滚动或更新都会触发全量渲染，导致性能瓶颈

### 1.2 性能瓶颈分析

```python
# 原始实现（优化前）
def _formatted_output(self):
    # ... 获取所有行
    text = "\n".join(lines)  # 连接所有4000行
    return self._ANSI(text)  # 渲染所有行
```

## 3. Aegis 视口裁剪实现

### 3.1 设计思路

结合 Hermes 的简洁性和 Claude Code 的视口概念，实现轻量级视口裁剪：

1. **计算可见区域**：基于滚动位置和视口高度
2. **添加缓冲区**：在可见区域上下各添加50行缓冲
3. **只渲染可见部分**：避免处理不可见的历史行

### 3.2 实现细节

**文件位置：** `src/aegis_agent/tui.py`

#### 3.2.1 新增常量
```python
_VIEWPORT_BUFFER_SIZE = 50  # 视口上下缓冲区大小
```

#### 3.2.2 修改的 `_formatted_output()` 方法
```python
def _formatted_output(self):
    with self._lock:
        lines = list(self._lines)
        live = self._live_renderable
    if live is not None:
        live_text = _render_to_ansi(live, theme=self._theme).rstrip("\n")
        if live_text:
            lines.extend(live_text.splitlines())
    if not lines:
        return [("class:aegis.dim", "")]

    # 视口裁剪：只渲染可见行加上缓冲区
    viewport_height = self._history_viewport_height()
    self._last_max_scroll = max(0, len(lines) - viewport_height)

    if self._follow_output:
        self._history_scroll = self._last_max_scroll
    else:
        self._history_scroll = min(self._history_scroll, self._last_max_scroll)

    # 计算带缓冲区的视口范围
    scroll_pos = self._history_scroll

    # 从滚动位置开始（上方带缓冲区）
    start = max(0, scroll_pos - _VIEWPORT_BUFFER_SIZE)
    # 结束于滚动位置 + 视口高度（下方带缓冲区）
    end = min(len(lines), scroll_pos + viewport_height + _VIEWPORT_BUFFER_SIZE)

    # 只渲染可见部分加缓冲区
    visible_lines = lines[start:end]
    # ScrollablePane 只看到了切片，因此必须换算为切片内坐标
    self.scroll.vertical_scroll = scroll_pos - start
    text = "\n".join(visible_lines)
    return self._ANSI(text)
```

#### 3.2.3 全局坐标与切片坐标必须分离

`_history_scroll` 表示完整历史中的绝对位置；`ScrollablePane.vertical_scroll`
表示当前 `visible_lines` 切片中的局部位置。两者不能复用。若把数千行历史中的绝对位置直接交给
只有约百行的切片，prompt_toolkit 会尝试滚到切片范围之外，表现为滚轮突然卡住、内容空白，或尾部
thinking 颜文字不可见。

换算关系为：

```text
local_scroll = absolute_scroll - slice_start
```

流式输出增长时，用户若已经上滚，`_history_scroll` 保持不变；只有重新计算出的切片范围和局部坐标
发生变化。用户回到底部后才恢复自动跟随。

### 3.3 关键算法

#### 视口范围计算
```
start = max(0, scroll_pos - BUFFER_SIZE)
end = min(total_lines, scroll_pos + viewport_height + BUFFER_SIZE)
```

#### 渲染行数
```
渲染行数 = min(total_lines, viewport_height + 2 * BUFFER_SIZE)
```

## 5. 实现优势

### 5.1 相比 Hermes
- **更精确的视口控制**：Hermes 依赖 prompt_toolkit 内置功能
- **主动性能优化**：主动裁剪而不是被动限制

### 5.2 相比 Claude Code
- **更轻量级**：不需要 Yoga 布局引擎
- **更简单实现**：直接基于行号裁剪
- **更低开销**：不需要复杂的屏幕缓冲区管理

### 5.3 独特优势
- **恒定渲染时间**：无论历史多长，渲染时间基本不变
- **平滑滚动**：缓冲区确保滚动时不会出现空白
- **内存高效**：只处理可见内容，减少内存使用

## 6. 边界情况处理

### 6.1 滚动边界
- 顶部边界：`start = max(0, ...)`
- 底部边界：`end = min(total_lines, ...)`

### 6.2 跟随输出
- 当 `_follow_output=True` 时，自动滚动到底部
- 当用户手动滚动时，禁用跟随输出
- 流式内容继续增长时保留 `_history_scroll`，不会把用户的阅读位置拖走
- thinking 状态作为 live tail 参与同一套裁剪与坐标换算

### 6.3 视口高度计算
```python
def _history_viewport_height(self) -> int:
    """计算可用行数（减去分隔符和输入框）"""
    try:
        return max(1, self.app.output.get_size().rows - 2)
    except Exception:
        return 22  # 默认值
```

### 6.4 滚动控件与快速回底

- 隐藏 `ScrollablePane` 自带滚动条：该滚动条只知道当前缓冲切片，长度不能代表完整历史，且当前
  界面没有实现拖动语义。
- 鼠标滚轮继续每事件移动一行，PageUp/PageDown 继续用于分段浏览。
- `Ctrl+End` 一键将 `_history_scroll` 设为当前尾部，并恢复 `_follow_output=True`；后续流式输出会
  继续贴着底部显示。
